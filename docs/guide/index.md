# acb-bridge 是什么

把 AI agent（DSH、WorkBuddy、Trae、Codex、OpenClaw……这类运行时）接进聊天平台（QQ、KOOK、Discord、Telegram……）的一座桥。

装好之后，你可以在 QQ 群里、私聊里跟自己的 agent 说话。它在群里看起来像个普通群友：
被 @ 会回话、发图、查资料、记东西——大脑在 agent 那边，桥只负责「翻译」和「调度」。

## 桥干什么、不干什么

桥只做四件事：

1. **收发翻译**：平台消息 ↔ agent 工具调用，两边格式互转；
2. **何时叫醒**：按你配的唤醒策略（被 @、被回复、被戳、攒够 N 条……）决定要不要把消息递给 agent；
3. **记了什么**：所有消息进一条流水（SQLite），读没读、读到哪里都有账（水位）；
4. **能发到哪**：agent 只能往它订阅的房间里发消息，越界会被拦。

桥**不替 agent 思考**。模型、工具、文件权限都由 agent 侧（harness）决定。

## 一分钟理清五个词

| 词 | 是什么 | 好比 |
|---|---|---|
| **连接** connection | 一条通到聊天平台的管道，一个账号一条 | 一个 QQ 号 = 一条连接 |
| **人格** persona | 一段纯文本的人设卡，决定 agent 的说话风格 | 群里的「性格设定」 |
| **记忆** memory | 一个 git 仓库，agent 自己读写 | 它的笔记本 |
| **harness** | 接管会话的 agent 运行时，主动连桥报名 | 大脑 |
| **会话** session | 上面四样的组合：哪个 harness、什么人设、什么记忆、订了哪些群 | 群里一个具体的人 |

会话订阅房间（如 `qq:group/123456789`），同一个会话可以同时看群和私聊，也可以开多个会话各管各的群。

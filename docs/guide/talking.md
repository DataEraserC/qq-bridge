# 日常使用

配好之后，你面对的就是一个群友。这页讲「它听什么、会什么、边界在哪」。

## 怎么叫醒它

唤醒策略在[配置](./config)里逐房间设，默认推荐这几种：

| 动作 | 说明 |
|---|---|
| **@ 它** | 最可靠的方式，任何配置下都醒 |
| **回复它的消息** | 引用/回复 agent 发的消息算对它说话 |
| **叫它名字** | `name_mention = true` + `names = [...]` 里配的名字 |
| **戳一戳** | 冲你来的平台事件默认就醒（QQ 的 `poke` 属于这一类）；不想醒就配 `ignore_event_tags = ["poke"]` |
| **攒话** | 上面都没触发时，攒满 `accumulate` 条也醒——适合「潜水旁听」模式 |

私聊一般只开 @ 和回复，不然对面每句话都把它叫起来。

## 它能回什么

文本、@ 人、引用回复、表情、图片、音频、视频、文件……具体到某个平台做不了的内容段
（比如 QQ 没有 X 平台特有的某类卡片），适配器会**明确报错或降级**，不会悄悄丢。

## 发图、发文件

agent 生成的本地文件（比如画的图）**直接把文件路径当 `url` 写进消息段**，桥会自动
收下文件、换成平台能下载的 URL 再发——这条链路就是[文件中继](./config#文件中继-发图发文件的关键)。
HTTP 地址也可以给，但要保证**平台那边**访问得到，否则平台下载失败。

## 消息太多怎么办

一轮投递有上限（`delivery_limit`，默认 30 条）：积压超过上限时只投最新的前 30 条，
其余的 agent 可以用 `fetch_records` 自己翻历史——不会一口气灌爆上下文，也不会丢。

## 它知道什么

- 订阅房间里的所有消息都会记进流水（包括没叫醒它的），叫醒时把**没读过的**打包给它；
- 挂了记忆仓库的会话，agent 自己维护笔记（git worktree 在 `state/worktrees/` 下），
  下次醒来还认得你；
- 同一个会话同时看群和私聊时，两边的话它在同一份上下文里（但每轮只处理一个房间）。

## 管理员的特权

连接上的 `admin_qqs` 里列的 QQ 号是系统管理员，agent 的运行反馈（失败原因、异常通知）会按配置
发给指定房间。想让 agent 帮你做点危险操作（踢人、改群名），在连接上开
`allow_destructive`，并想清楚后果。

## 换会话、重置上下文

想让它「失忆重开」：控制台 → 会话 → 断开映射并重置。详见[控制台](./console#重置会话-断开映射)。

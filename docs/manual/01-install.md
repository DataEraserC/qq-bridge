# 安装与启动

> 当前仓库没有可运行的代码。本文描述建成后的安装方式，字段与行为以 [架构文档](../architecture/README.md) 为准。

## 依赖

| 组件 | 作用 | 是否由 qq-agent-bridge 提供 |
| --- | --- | --- |
| OneBot 实现 | 登录 QQ，提供 WebSocket 事件与动作接口 | 否，自备（如 SnowLuma、Lagrange） |
| 内核 | QQ 侧语义 | 是，单个二进制 |
| 适配器 | 对接 agent 运行时 | 是，按运行时的生态分发；DSH 适配器是 Node 包 |
| agent 运行时 | 提供模型与工具调用 | 否，自备 |

## 启动顺序

1. 启动 OneBot 实现，确认它能正常收发消息，记下 WebSocket 地址与访问令牌。
2. 启动内核，它会连接全部已配置账号。
3. 启动适配器，它连内核的本机 socket。
4. 在 agent 运行时里把适配器注册为工具服务端。

顺序不严格——内核和适配器都会重连——但按这个顺序启动时，日志里不会有误导性的失败。

## 目录

| 路径 | 内容 |
| --- | --- |
| `config.toml` | 唯一配置文件 |
| `state/` | 归档、水位、适配器的记忆名映射 |
| `personas/` | 人格文本（若用 `file` 引用） |
| `hooks/` | Lua 脚本（若用 `file` 引用） |

`state/` 与 `config.toml` 不应提交到版本库。

## 验证启动成功

内核日志里应看到：

- 每个账号一条「已连接」。
- 配置校验通过（若有 `(群, 账号)` 冲突，这里会失败并列出冲突项）。

适配器日志里应看到：

- 与内核握手完成，协议版本一致。

在群里发一条消息，内核日志应出现一次唤醒判定结果；若判定为唤醒，随后出现一次投递。

## 常见启动失败

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 内核启动即退出，日志列出两组设备 | `(群, 账号)` 冲突 | 见 [配置](02-config.md) 的冲突规则 |
| 适配器反复重连 | 内核未启动，或 socket 路径不一致 | 检查两侧配置的 socket 路径 |
| 握手被拒 | 协议主版本不同 | 内核与适配器版本需匹配 |
| 账号连不上 | OneBot 实现的地址或令牌错误 | 先用 OneBot 实现自带工具验证 |

# 不变量

以下行为**不可配置、不可由钩子绕过、不可由适配器协商**。任何改动若触碰其中一条，需要先改这份文档并说明理由。

## 一、自身账号的消息不算新消息

设备声明的账号集合里任一账号发言，该事件标记为「自己」：写入归档，不进未读，不触发唤醒。

**执行位置**：身份过滤阶段，在 `preReceive` 钩子之前。

**为什么不可配置**：两个设备各自持有一个号时，A 号会看到 B 号发言，`user_id ≠ self_id`，按普通群友处理。若这条做成可配置，写错一次就是两个号互相回复、无限刷 token。这是身份识别，不是规则。

## 二、串行队列的键是记忆名

同一记忆名的投递严格串行，一个回合结束后才投递下一批。

**为什么不可配置**：会话标识会因运行时回收而重建。按会话标识做键，重建窗口里会出现两条并行队列，把两条消息同时灌进同一个新会话。

## 三、同一个 `(群, 账号)` 只属于一个设备

启动期检查。冲突即启动失败，不降级、不警告后继续。

**为什么不可配置**：冲突意味着同一个账号的同一份消息流进入两个设备的记忆，两边各自回复。这不是「配置不当」，是配置无意义——没有一种行为是部署者想要的。

## 四、回合票一次性

票在回合结束时作废。过期票、未知票、跨回合复用一律拒绝。

**为什么不可配置**：票是工具调用的身份来源。允许复用等于允许一个回合的动作被另一个回合冒用。

## 五、工具的参数语义在内核

适配器只声明工具的形状（名字、描述、参数 schema），不解析参数含义，不做权限判断。

**为什么不可配置**：适配器不掌握范围信息。若由适配器判断「能不能发到这个群」，它就必须知道群号，边界立刻破掉。

## 六、脚本来源只能是配置

钩子脚本来自 `config.toml` 或其引用的文件。不接受模型输出、群消息、网络内容作为脚本。

**为什么不可配置**：这不是权限问题，是信任来源问题。脚本能改变唤醒判定，而唤醒判定决定「要不要说话」——让群友能写这段逻辑，等于让群友决定 agent 什么时候开口。

## 七、适配器不重试投递

投递失败的重试由内核驱动。适配器只上报失败。

**为什么不可配置**：两侧各自退避会叠加，实际间隔变成两者乘积，且不可预测。重试节奏必须只有一个所有者。

## 八、钩子失败偏向保留

`preReceive` 抛错时事件保留；`shouldWake` 抛错时不否决。

**为什么不可配置**：脚本 bug 的代价应该是噪音，不是失联。反过来（抛错即丢弃）会让一个语法错误变成静默的永眠。

## 检查单

改动代码前对照：

- [ ] 是否让适配器知道了群号、账号或消息段？
- [ ] 是否让内核知道了会话、回合或工具调用的运行时形态？
- [ ] 是否把上面八条之一变成了可配置项？
- [ ] 是否新增了「需要同时知道两侧」的逻辑？（应该是协议消息）
- [ ] 是否让某个动作的身份来源从回合票变成了别的什么？

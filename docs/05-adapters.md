# 适配器：把平台接进桥

适配器是桥与聊天平台之间唯一的一层。核心不认识 QQ，也不认识 OneBot；适配器负责把平台
的话翻译成核心能懂的形状，再把核心要发的东西翻译回去。

## 一件必须先定下来的事：房间怎么写

平台名与房间号一起决定一个房间，中间用冒号隔开。QQ 有群和私聊两种场所，所以房间号
里带类型：

| 场所 | 房间写法 | 例子 |
|------|----------|------|
| QQ 群 | `qq:group/<群号>` | `qq:group/123456789` |
| QQ 私聊 | `qq:private/<对方号>` | `qq:private/10001` |

来源：实现默认，可推翻。这样写的好处是同一个平台的不同场所不会撞号，适配器一眼就能
判断该调 `send_group_msg` 还是 `send_private_msg`。

## 配置

```toml
[[adapters]]
platform = "qq"        # 要跟房间前缀一致
kind = "onebot11"      # 目前只有这一种
url = "ws://127.0.0.1:3001"
```

- 一个平台只能配一个适配器，配两个会在启动时报错。
- 只支持 `ws://`。`wss://` 要额外拉 TLS 依赖，等真有需要再加。
- 地址里可以带查询串，比如 `ws://127.0.0.1:3001?access_token=xxx`——查询串会原样带到
  握手请求里，很多 OneBot 实现就是这么鉴权的。
- 房间的平台名在订阅里配了，但没配对应适配器，启动时会打一行提醒：那个房间发不出去。

## OneBot 11 走哪种连接

用**正向 WebSocket**：桥作为客户端，连到 OneBot 实现（NapCat / Lagrange / go-cqhttp 等）
开出来的 WS 服务端。

来源：实现默认，可推翻。理由只有一个：反向 WS 要桥自带一个 WS 服务端，多一层监听和鉴权，
正向只要一个地址就能跑。真需要反向，加一种 `kind` 即可，不影响其它部分。

### OneBot 侧必须设的一项

**消息格式要设成 `array`**（`post-format=array` / `messagePostFormat: "array"`）。

设成 `string`（CQ 码）也能跑，但适配器认不出 `[CQ:at,qq=...]` 这种文本里的 @，
于是「@ 我才醒」就永远不生效。这不是适配器的锅，是平台没给结构化数据。

## 事件怎么映射

| OneBot 事件 | 变成什么 | 说明 |
|-------------|----------|------|
| `post_type=message`，`message_type=group` | 一条消息，房间 `qq:group/<群号>` | 发送者名字优先用群名片，其次昵称 |
| `post_type=message`，`message_type=private` | 一条消息，房间 `qq:private/<号>` | |
| `post_type=notice`，`notice_type=notify`，`sub_type=poke` | 平台事件 `poke`，正文「[拍了拍我]」 | 拍的是我则标记「冲我来」，唤醒策略据此判定 |
| 其它 `notice` | 平台事件，事件类型就是 `notice_type` | 进退群、禁言、撤回等，正文是一句人话 |
| `post_type=request` | 平台事件 `request_<类型>` | 加好友、加群邀请 |
| `post_type=meta_event` | **不记** | 心跳每几秒一次，记下来只会把流水撑爆 |
| `post_type=message_sent` | **不记** | 自己发出消息的回执，桥在发送时已经记过 |

消息、拍一拍、其它事件走的是同一条路（ADR-0005）：都变成一条记录，交给桥决定要不要
算未读、要不要叫醒。拍一拍没有特殊逻辑。

## 内容元素怎么翻译

出去（桥 → QQ）：

| 元素 | OneBot 段 | 备注 |
|------|-----------|------|
| text | `text` | |
| at | `at`，`all` 时 `qq="all"` | |
| quote | `reply` | |
| image / audio / video | `image` / `record` / `video` | 用直链当 `file` |
| face | `face` | |
| file | **报错** | OneBot 11 没有标准文件段，明确报错而不是悄悄丢 |
| opaque（platform=qq） | 原样送出 | 平台特有内容照搬 |
| opaque（别的平台） | **报错** | 别处的内容发不到 QQ |

进来（QQ → 桥）：

| OneBot 段 | 元素 |
|-----------|------|
| `text` / `at` / `reply` | text / at / quote |
| `image` / `record` / `video` | image / audio / video，优先取直链，取不到用平台内部文件名 |
| `face` | 表情，带平台名与 id |
| 其它（卡片、合并转发、markdown…） | 不透明载荷，原样留着，编回 QQ 时照抄 |

## 连接出问题会怎样

- **连不上**：每 5 秒重试一次，不退出进程。OneBot 后开也能连上。
- **断了**：自动重连；断在轮次中间的那一轮作废，没确认的消息仍是未读，下一轮重投。
- **发消息时没连上**：工具调用直接返回错误，不假装成功。
- **发消息等回话超时**：10 秒没回就报错。平台真的卡住时，AI 知道这次没发出去。

连上之后适配器会问一次「你登录的是哪个号」（`get_login_info`）。如果这个号和订阅里
配的 `send_account` 对不上，会打一行提醒——因为对不上就意味着自己说的话会被当成别人
说的，严重时会自己回自己。

## 已知限制

1. 不支持 `wss://`。
2. 不支持反向 WebSocket（桥当服务端）。
3. 发文件会报错：OneBot 11 没有标准的文件段，各实现的扩展不统一，不做猜测。
4. 合并转发只能收、不能主动发（发的时候是原样透传，能不能成看平台实现）。
5. 一条连接对应一个登录账号。要同时挂两个 QQ 号，就配两个平台名（如 `qq` 和 `qq2`）
   各连一条——这是配置层的限制，不是设计上的。

## 怎么验

平台这一侧只有真环境能验。拿真的 OneBot 地址填进配置后：

```bash
# 1. 先只检查配置，不启动
cargo run -p qqab-bridge -- --config config.toml --check

# 2. 起桥
cargo run -p qqab-bridge -- --config config.toml

# 3. 另开一个终端，用开发用的最小 harness 接上去
cargo run -p qqab-bridge --bin dev-harness -- --token <配置里的 token>
```

然后在群里 @ 一下那个号，桥上应当看到：

```text
适配器 qq：已连上 ws://127.0.0.1:3001
适配器 qq：登录账号 10001
```

harness 那边应当看到投递过来的记录，并自动回一句话；群里能看到那句话，就说明整条链
通了（收 → 记 → 醒 → 投 → 发 → 回流）。

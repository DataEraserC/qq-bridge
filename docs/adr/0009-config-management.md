# ADR-0009 配置管理：Web 管理页 + 轮次边界重载，不进 agent 工具面

来源：用户裁定（不做成 agent 工具、要有配置页面、轮次边界重载均为用户拍板）。技术选型为实现默认。

## 这条决定了什么行为

- 配置修改**不是 agent 工具**。agent 不能改订阅、策略、人格——配置就是权限边界，能改配置就能解开 `send_message_to` 的目标封死，安全设计全部作废。
- 管理员通过桥**自带的 Web 管理页**改配置：查看/编辑设备、订阅、策略参数、人格、账号连接信息。敏感字段（令牌、密码）页面上遮蔽显示。
- 为什么自带而不是借宿主的配置界面：桥是独立进程，不寄生于任何 harness，不能假设某个 harness 提供配置 UI。自带一个最小的 Web 管理页在哪个宿主下都成立。
- 改完**不立即生效**，走**轮次边界重载**：正在跑的轮次用旧配置跑完，下一轮开始时用新配置。轮次是天然的切换点，不存在「订阅改到一半一轮正在跑」的边界情况。
- 管理页要鉴权（管理员令牌），默认只监听本机；要暴露到局域网时由管理员自己配。

## 不这样会怎样

- 做成 agent 工具：agent 一次幻觉或一次被诱导，就能把自己发消息的范围改到任意房间——权限边界形同虚设。
- 让用户手改文件：容易改出非法配置，也没有校验和反馈；用户不该需要懂文件格式。
- 立即生效：正在跑的轮次一半用旧订阅一半用新订阅，行为无法解释；轮次边界重载没有这个问题。

## 技术细节

Web 管理页 = 同进程里的 HTTP 服务（静态页面 + 一组管理 API），写权限落盘到配置文件并做完整校验，校验失败拒绝保存并提示。重载实现为：配置加载进核心时打版本号，每轮开始取当前版本，跑到一半不变。管理 API 与 harness 接入协议完全分离，鉴权各自独立。

## 实现注记（2026-10-31）

- 编辑形式：管理页提供 **TOML 原文编辑器**（`GET/POST /api/config/toml`）。保存顺序是先校验后落盘——`Config::parse` 不过就一个字节都不写；落盘前自动备份成 `<配置路径>.bak`。校验通过的新配置**暂存**进桥（`stage_config`），不立即生效。
- 暂存配置在两个点换上（`apply_staged_config`）：**收消息（ingest）**和**开轮（poll_turn/poll_turn_for）**。收消息处也要换，否则刚保存的新订阅会漏掉紧接着来的第一条消息。
- 已知权衡：换配置的瞬间若有别的会话的轮次正在跑，那个轮次**后续的工具查询**（订阅校验、记忆定位等）会看到新配置。投递批次不受影响——它在开轮时组装，组装完就不变。严格做到「每个轮次冻结自己那份配置」要给每轮存快照，等真出现实际混淆再做。
- **要重启才生效**的边界由控制台逐项对比报告（`reload_impact`）：监听地址（endpoint/console/file_relay.listen）、connections（守护线程持有旧连接信息）、storage.path、worktrees_root。其余（会话/订阅/唤醒/人格/记忆/保留策略等）下一轮自动生效。
- 「放弃暂存」：`POST /api/config/discard`，存错了还没到下一轮时可以撤回。

# ADR-0002 订阅模型：设备订「连接 + 房间」，订阅上挂三条可替换的策略

来源：用户裁定（2026-10-25 对话确认；2026-10-29 补充「订阅 = 连接 + 房间」与「一把令牌代表
一组设备」两条）。

## 这条决定了什么行为

- 设备 = 一个虚拟实体：订阅若干房间，有一个人格、一份记忆、一个接入令牌。与硬件无关。
- 订阅 = **一条连接 + 一个房间** + 三条策略：
  - **接收策略**：这个房间来的哪些消息算未读；
  - **发送策略**：往这个房间发消息用哪个账号——账号是连接的属性（一个号一条连接），
    订阅不再单独写它；
  - **唤醒策略**：这个房间的消息什么时候叫醒设备。
- 三条策略都有内置默认实现，用户可以替换成自己的逻辑（内嵌脚本或外置进程）。
- 收发的合法目标全部由订阅表决定，表里没有的房间一律拒绝。
- **一把接入令牌可以代表一组设备**：配置里几台设备写同一个 token，它们就是一组，由同一个
  harness 会话代表。这一组能说话的范围 = 这组设备订阅的并集；越界拒绝。同一个房间被组内
  两台设备都订了时，发消息要指明用哪台的身份（`device` 参数），否则拒绝并说清楚。
- 一台设备只能由一个 harness 会话代表，但一台 harness 会话可以代表多台设备——这是「跨设备
  说话」能成立的前提，也是它唯一的入口（参数里没有别的设备 id）。

## 不这样会怎样

如果唤醒规则挂设备级（旧实现的做法），一个设备跨平台时两边被迫用同一套规则——「QQ 群除老王外都叫我，Discord 只在 @ 我时叫我」写不出来。如果收发过滤散落在代码各处，「谁能给我发消息」「我能发给谁」没有一处能查，权限边界形同虚设。

## 技术细节

策略机制与旧实现的钩子宿主同构：默认实现内置编译；自定义支持 Lua 内嵌与外进程常驻两种形态，带资源限额与超时。订阅条目是收发的唯一权限来源，工具面与调度只查表不判逻辑。

## 补充裁定：工具可见域按会话圈（2026-11-01）

来源：用户裁定。上文「这一组能说话的范围 = 这组设备订阅的并集」**只对发送成立过一段时间，现读发全部按会话圈**：工具面（list_rooms / get_history / fetch_records / 笔记 / 事件）只看得见**当前轮次会话**订阅的房间，连接上兄弟会话的房间不可见。

为什么改：设备概念已删，串行单位是会话；一条连接可以挂多个会话，而它们在 harness 侧是**各自独立的大脑**（opencode 一个实例带多条独立会话，不是同一个大脑的分身）。组视图会让一个会话的 agent 自称管着兄弟会话的房间（真机实测踩过：agent 报「订阅 3 个房间」，其中 1 个是兄弟会话的）。dsh 等每条连接单会话的部署两种视图等价，不受影响。

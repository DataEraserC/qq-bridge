# ADR-0002 订阅模型：设备订房间，订阅上挂三条可替换的策略

来源：用户裁定（2026-10-25 对话确认）。

## 这条决定了什么行为

- 设备 = 一个虚拟实体：订阅若干房间，有一个人格、一份记忆、一个串行处理队列。与硬件无关。
- 订阅 = 一个房间 + 三条策略：
  - **接收策略**：这个房间来的哪些消息算未读；
  - **发送策略**：往这个房间发消息用哪个账号；
  - **唤醒策略**：这个房间的消息什么时候叫醒设备。
- 三条策略都有内置默认实现，用户可以替换成自己的逻辑（内嵌脚本或外置进程）。
- 收发的合法目标全部由订阅表决定，表里没有的房间一律拒绝。

## 不这样会怎样

如果唤醒规则挂设备级（旧实现的做法），一个设备跨平台时两边被迫用同一套规则——「QQ 群除老王外都叫我，Discord 只在 @ 我时叫我」写不出来。如果收发过滤散落在代码各处，「谁能给我发消息」「我能发给谁」没有一处能查，权限边界形同虚设。

## 技术细节

策略机制与旧实现的钩子宿主同构：默认实现内置编译；自定义支持 Lua 内嵌与外进程常驻两种形态，带资源限额与超时。订阅条目是收发的唯一权限来源，工具面与调度只查表不判逻辑。

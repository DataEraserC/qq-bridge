# ADR-0003 轮次串行；一轮只投触发会话的未读；记录、未读、笔记按房间记

来源：用户裁定（选项二由用户选定；串行处理由用户确认为类人设计）。

## 这条决定了什么行为

- 同一设备的轮次严格串行：一轮没收工，新来的消息只攒不处理，等收工后由各自唤醒条件开下一轮。不同设备之间并发。
- 一轮只投递**触发那一轮的房间**的未读；其它房间的未读原地等着。回复目标不用选，就是本轮的房间；要发别处用 `send_message_to`。
- 未读按房间各自累积，水位是每房间一个游标；流水是每房间的完整日志，投递只推水位、不改流水。
- 笔记按房间隔离，主键带平台——QQ 群 123 和 Discord 频道 123 的笔记绝对不串（旧实现的已知缺陷，这次从设计上堵死）。

## 不这样会怎样

- 如果一轮打包所有房间的未读：agent 要在一次处理里分辨「这句话回哪个房间」，工具面被迫加目标选择，复杂度上去了，收益只是省一轮时间。
- 如果不串行：同一份记忆被两轮并发读写，agent 的上下文会互相踩，相当于一个人同时接两个电话。
- 如果笔记主键不带平台：跨平台必串台。

## 技术细节

串行键 = 设备的记忆名。队列按记忆名串行化；轮次上下文（回合票）携带本轮房间，是发送与投递的唯一身份来源。

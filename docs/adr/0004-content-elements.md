# ADR-0004 内容元素：标准元素表 + 降级 + 不透明透传

来源：用户裁定（跨平台中立要求由用户提出；「不只收 text」由用户裁定）。细节为实现默认。

## 这条决定了什么行为

消息内容用**内容元素数组**表达，不用裸文本。核心定义一张标准元素表（第一版 8 个）：

| 元素 | 说明 |
|------|------|
| text | 纯文本 |
| at | 提及某人（或全体） |
| quote | 引用回复某条消息 |
| image / audio / video / file | 嵌入资源 |
| 表情 | 平台表情，带平台侧 id |

三条转换规则，适配器必须遵守：

1. **最大程度适配**：每个标准元素尽力编成平台格式；
2. **降级或报错**：平台不支持时降级到最接近的等价物（如引用降成「回复：原文」文本），降不了就明确报错——**绝不悄悄丢弃**；
3. **不透明透传**：平台特有内容（KOOK 卡片、Discord embed）装进带平台标记的不透明载荷原样携带，核心不解释。把收到的卡片原样引回原平台是合法操作。

## 不这样会怎样

只收 text：@、引用、图片发不出去，agent 在群聊里半残。照搬 OneBot 消息段：概念和类型绑死 QQ 生态，KOOK/Discord 的实现会被迫削足适履。让核心认识每个平台的高级内容：核心膨胀，违反「平台语义往下压到适配器」的原则。

## 技术细节

参考 Koishi 的 element 体系（标准集 + 降级语义）与 NoneBot 的 MessageSegment（type + data）。元素用 `{type, data}` 形状表达，序列化友好。标准元素表只增不改：加元素是兼容演进，改语义不是。

## 补充裁定：「核心不解释」不等于「模型看不见」

来源：用户裁定（2026-10-30 用户指出渲染成一句话的占位是错的）+ 实现默认（截断长度）。

**事情是这样**：真机上收到一条 QQ 合并转发，库里存得完全正确（`{"type":"opaque","platform":"qq","payload":{"type":"forward","data":{"id":"…"}}}`），但渲染给模型的文本只有一句「[qq内容，核心不解释]」——**载荷整个被丢掉了**，模型看到等于没看到。

**划清两件事**：

- **桥（core）不解释**：桥不解析卡片/embed/转发的语义，照搬即可。这条不变。
- **渲染层必须把原始载荷摊给模型**：桥不解释是「桥不做判断」，不是「模型不该知道」。送进对话的文本是唯一通道，把载荷换成一句占位，等于这条内容在对话里凭空消失，直接违反本 ADR 规则 2 的「绝不悄悄丢弃」。

**落地**：`harnesses/*` 的 `renderElements` 对 `opaque` 输出 `[<平台> 平台特有内容，原样如下：<紧凑 JSON>]`，超过 600 字符截断并标注「已截断」；不认识的未知类型也同样把 JSON 摊出来，不再只报类型名。

**已知边界**：模型现在知道「这是合并转发、平台 id 是 X」，但**还取不到转发里的正文**——那需要适配器提供 `get_forward_msg` 之类的工具（属于新增能力，不在本 ADR 范围内）。

# 内核用 Rust，适配器用 TypeScript

内核用 Rust 编写，适配器用 TypeScript 编写。

## 理由

**内核选 Rust**：常驻进程，持有全部长连接与归档，对内存占用和长时间运行的稳定性有要求。Rust 同时给出一份无运行时依赖的单二进制，便于分发。

**适配器选 TypeScript**：它的全部工作是接一个 agent 运行时的工具接口。这类运行时的 SDK 与工具协议实现集中在 JavaScript/TypeScript 生态（MCP SDK 即在其中）。用别的语言写适配器，等于自己重写一层协议实现，且要跟着上游的接口演进而维护。

## 考虑过的方案

**两侧都用 Rust。** 适配器需要 MCP 的 Rust 实现，并要跟随该协议的演进。收益是单一语言与统一构建，代价是适配器从「薄转发层」变成「协议实现层」。

**两侧都用 TypeScript。** 内核会失去单二进制分发与内存控制，且长连接与归档的稳定性不如 Rust。

## 后果

- 构建链有两套：Cargo 与 Node 包管理。CI 需要两者。
- 协议成为跨语言接口，字段演进需要两侧同步。这也是协议里「未知字段忽略、主版本不同即拒绝」这两条规则存在的原因。

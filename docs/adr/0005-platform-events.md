# ADR-0005 平台事件：记进流水，不实时推送

来源：用户裁定（默认记录、只对订阅的房间记录由用户拍板；「不实时推送」由实现默认补充，可推翻）。

## 这条决定了什么行为

- 房间里的非消息事情——拍一拍、成员进出、频道创建、文件上传——统称平台事件。
- 适配器把不认识的事件解成通用形状：`{ 类型, 房间, 原始数据 }`。核心不解释内容，只做记录。
- **默认记录**进流水，但**只对设备订阅的房间**记；未订阅房间的事件什么都不做。
- 记录成一行可读文本，和普通消息一样能进下一轮的上下文。
- 不给 harness 实时推送：agent 最早在下一轮看到事件。将来如果需要「某类事件立刻叫醒」，给唤醒策略加一条按事件类型匹配即可，不需要新通道。

## 不这样会怎样

旧实现把不认识的事件塞进 `Ignored{kind}`，只有日志能看到，agent 永远不知道「有人把我拍了」——用户明确纠正过这一点。反过来若做实时推送：DSH 这类 harness 没有接收异步通知的口子，推过去没人接；还会打断回合模型。

## 技术细节

事件类型用字符串前缀命名（如 `kook.channel.created`），记录时带原始 JSON，翻流水能还原现场。

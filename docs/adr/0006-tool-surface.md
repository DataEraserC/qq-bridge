# ADR-0006 工具面：发送 + 读取，目标被订阅封死，身份靠回合票

来源：用户裁定（两个发送工具的形状、to 受订阅限制、不只收 text、要加读取类工具均为用户裁定）。具体清单为实现默认。

## 这条决定了什么行为

agent 在一轮里可以调用的工具：

| 工具 | 参数 | 行为 |
|------|------|------|
| `send_message` | elements | 发到本轮房间 |
| `send_message_to` | elements, to | 发到指定房间；`to` 的可选目标 = 本设备的全部订阅，越界拒绝 |
| `get_history` | room, before, limit | 查订阅房间的流水 |
| `list_rooms` | — | 列出本设备订阅的房间 |
| `get_notes` / `set_note` / `del_note` | room, key, value | 笔记读写 |
| `get_platform_events` | room, limit | 查最近的平台事件 |
| `wait_message` | room, timeout | **阻塞**等该房间来新未读，等到就作为工具结果返回（自动确认）；超时返回空。上限受配置约束 |
| `ack_messages` | ids | 确认这批消息已处理完；水位只前进地推到连续位置，未确认的下一轮重投（见 [0010](0010-ack-watermark.md)） |

铁律：

- 两个发送工具参数形状一致，降低使用成本；
- 没有任何工具能发到订阅之外的房间；不给 `send_message` 加自由 `to` 的变体；
- 没有自由设定水位的工具——水位只经 `ack_messages` 前进；
- 每次工具调用必须携带回合票，票在开轮次时签发、收工时作废——不认票不认调用。

## 不这样会怎样

给 `send_message` 加自由 `to`：agent 一个幻觉就能把 A 群的话发到 B 群，权限边界崩塌。只做受限的「转发」工具：只许传文本，@、引用、图片都发不了，不合理（用户明确否决过这个形状）。不验票：上一轮作废的调用可以迟到执行，投到错误的对话里。

## 技术细节

工具在协议层是统一的请求/响应帧；每个工具一个处理函数，加工具 = 加函数 + 加测试，不改骨架。票绑定记忆名与房间，串行队列保证同票不会并发使用。

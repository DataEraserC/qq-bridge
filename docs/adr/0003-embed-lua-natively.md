# 钩子用内嵌 Lua，不用 WebAssembly

唤醒判定需要用户可编程，且要能表达否定条件（「除某人外都唤醒」）。决定用 Rust 内嵌 Lua 5.4（`mlua` + `vendored` 特性），不引入 WebAssembly 运行时。

## 理由

内核是 Rust。`mlua` 在 `vendored` 模式下把 Lua 源码一起编译进二进制，不需要系统装 Lua，也不新增运行时依赖。

脚本的定位是**配置**：由部署者手写几十行判定逻辑，不是需要分发的插件。这个定位下，WASM 的主要优势（跨实现可移植、强隔离）都用不上，而代价是真实存在的：多一条 WASM 运行时的构建链，多一层 ABI，多一套宿主函数约定。

## 考虑过的方案

**WASM 内嵌 Lua（例如经 wasmoon 或类似运行时）。** 在 Node 内核的前提下这曾是唯一选择——Node 里跑 Lua 只能靠 WASM。内核换成 Rust 后这个约束消失了。WASM 的收益是脚本能在不同实现之间移植，本项目没有这个需求。

**直接写 JavaScript（`node:vm` 之类）。** 同样以 Node 内核为前提。而且 `node:vm` 不是安全边界，用它做沙箱会给出错误的保证感。

**不做脚本，只做配置项。** 配置项无法表达任意否定条件，也无法按内容、时间、频率组合判断。「除某人外都唤醒」在规则表里没有位置——它需要否定，而规则表是正向条件的析取。

## 后果

- 脚本能力受 `mlua` 提供的标准库范围限制。沙箱靠不加载 `io`/`os`/`package` 实现，不是靠隔离执行。
- 威胁模型里脚本作者是部署者本人，目标是防误用，不是防恶意脚本。这一点必须在文档里写明，否则会被误当成安全边界。

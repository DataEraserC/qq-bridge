# 内核与适配器拆成两个进程

QQ 侧语义（账号、群、消息、唤醒）与 agent 运行时侧语义（会话、回合、工具调用）的变更速度、依赖、信任级别都不同。把它们放进一个进程，任何一侧的改动都要重启另一侧，且适配器的可替换性无法保证。决定拆成两个进程，之间只用一份本机 JSON 协议通信。

## 考虑过的方案

**单进程。** 旧实现的做法。缺点是换 agent 运行时要动 QQ 侧的代码，反之亦然；一侧崩溃拖垮另一侧。

**运行时的进程内插件。** 依赖特定运行时的内部 API（例如向任意会话注入提示的能力）。结构上更干净——身份来源可以从调用上下文直接拿到，不需要凭证——但把适配器绑死在那个运行时上，与「适配器可替换」直接冲突。

**外部守护进程 + HTTP。** 与最终方案同构，只是传输层不同。HTTP 需要占端口，且不天然限制在本机。Unix socket 同样满足「内核主动推送 + 双向低延迟 + 单机零端口」，且默认不暴露到网络。

## 后果

- 工具调用必须携带凭证（回合票），因为外部进程拿不到「现在是谁在调我」的结构化信息。
- 协议成为需要维护的接口。任何「需要同时知道两侧」的逻辑都必须落成协议消息，不能是共享代码。
- 内核可以比运行时活得久：运行时重启不导致 QQ 重连。

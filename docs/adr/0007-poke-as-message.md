# ADR-0007 拍一拍当消息处理

来源：用户裁定（旧实现缺陷由用户指出并要求纠正）。

## 这条决定了什么行为

拍一拍是一条普通的事件，走和别的平台事件同一条路：

1. 归档成一行可读正文（如「[拍了拍我]」）进流水；
2. 记入未读，下一轮投递时 agent 看得到「谁在什么时候拍了谁」；
3. 唤醒策略里的 `poke` 开关只决定「是否为此叫醒」，**永远不阻止记录**。

## 不这样会怎样

旧实现的缺陷：没有未读时拍一拍直接被吞——「把人拍了，agent 不知道」；有未读时投出去了，对话记录里也没有「谁拍的」。翻流水查不到，等于这事没发生过。

## 技术细节

拍一拍解成平台事件（类型 `poke`），带谁拍的、拍了谁；「冲着我来的」由核心判定，供唤醒策略用。
